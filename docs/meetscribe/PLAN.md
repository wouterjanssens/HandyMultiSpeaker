# MeetScribe – plan log

## 2026-10-26 – Phase 0: fork, build, recon

Plan:

1. Install missing tooling (rustup, bun, uv, cmake via Homebrew).
2. Use the existing fork `wouterjanssens/HandyMultiSpeaker` (origin) + `cjpais/Handy` (upstream);
   branch `meeting-mode`.
3. Build unmodified; run the dev build under our own bundle id so the installed Handy's data is
   never touched.
4. Recon → `ARCHITECTURE-NOTES.md`.

Outcome: done. Build OK. Key findings: upstream now uses `handy-recorder` + `transcribe-cpp` for
everything; transcribe-cpp has a (4-speaker, one-shot) Sortformer diarizer; NVIDIA's NeMo-Speech.cpp
has a native, Metal-capable, streaming C API for Nemotron 3 Diarization. See notes §5–6.

Open questions for Gate 0: project name; whether to replace the ONNX route (Phase 2) with
NeMo-Speech.cpp.

Plan: uv env in `research/`; offline + streaming scripts; real meeting audio with reference labels

## 2026-10-26 – Phase 2: native route (decision)

Plan change, approved by the owner ("do what you think"): instead of an ONNX export, use NVIDIA's
**NeMo-Speech.cpp** (Apache-2.0), which already implements Nemotron 3 Diarization streaming
natively (ggml, Metal) behind a stable C ABI (`nemo_speech/diar.h`) and ships an official
`q8_0.gguf`. Our job shrinks to: build it, verify parity with the Python reference, bind it from
Rust.

Status: **blocked on tooling permission** – the agent's sandbox refuses to configure/compile the
external repo. `scripts/meetscribe/build_nemo_speech.sh` builds and installs the SDK when run by
the owner. transcribe-cpp 0.4 does _not_ support Sortformer v3 (only v2.1, one-shot), so it is
not an alternative today (upstream request: handy-computer/transcribe.cpp#170).

Interim: handoff route C (Python sidecar) behind a `StreamingDiarizer` trait so the app works end
to end now; the native backend replaces it without touching alignment/UI.

## 2026-10-26 – Phase 4 (pulled forward): meeting mode in the app

Plan: pure logic in `crates/meeting-core` (clock, activity, alignment, live turns, segmenter,
export – unit-tested); app wiring in `src-tauri/src/meeting/` (capture tap pre-VAD with one sample
clock, diarizer + ASR workers, events, commands, settings in their own store); minimal marked
edits to upstream files; meeting window as a third Vite entry; Meetings settings page.

Outcome: implemented. End-to-end test with `MEETSCRIBE_SIMULATE_WAV` on the 4-min Dutch mix:
4/4 speakers, 48 turns, **100 % word-level speaker attribution** (530 words scored,
`research/score_meeting.py`). AMI real-meeting run: see Gate 4 notes below.
